# 🤖 Universal Status Bot v3.1 (Smart Logging & Groups)

**Universal Status Bot** — это продвинутая система централизованного мониторинга для ферм аккаунтов.
Она позволяет следить за статусом, прогрессом, ошибками и инвентарем (балансы, уровни) ваших софтов с десятков серверов через единый удобный Telegram-интерфейс.

> **🆕 Обновление v3.1:**
> * **📁 Реструктуризация:** Модули перенесены в папку `tgbotintegration` для избежания конфликтов имен.
> * **⚙️ Гибкая отправка логов:** Новые настройки в конфиге для управления отправкой файлов логов (при успехе или только при ошибках).
> * **⚡️ Multi-Window:** Поддержка запуска множества копий из одной папки (через `--worker`).
> * **🔄 Auto-Reset:** Автоматический сброс статистики при новом круге.

---

## 🔥 Ключевые возможности

* **📂 Умная группировка (Smart Grouping):** Бот наводит порядок сам. Если у вас запущены `Server`, `Server_Daily` и `Server_Classic`, он свернет их в одну папку **📂 Server**. На кнопке папки сразу видно состояние всех вложенных процессов: `🟢1 (Работает) 💤2 (Спят) 🔴0 (Ошибки)`.
* **⚡️ Multi-Window Support (Мульти-запуск):** Больше не нужно копировать папки с софтом! Запускайте основу, дейлики и тесты из **одной директории**. Просто добавьте флаг `--worker Daily` или введите имя при старте.
* **🔄 Auto-Reset (Авто-сброс):** Идеально для софтов, работающих 24/7. При начале нового цикла (на следующий день) статистика `500/500` сама сбросится в `0/500`.
* **📊 Живой Дашборд:** Отображение активных, спящих и упавших воркеров в реальном времени с детальной статистикой.
* **🤫 Silent Mode (Безопасный режим):** Выставьте `USE_TG_BOT = False` в конфиге воркера, и скрипт превратится в обычный софт. Он перестанет требовать Redis и отправлять уведомления. Идеально для передачи софта друзьям или тестов.
* **❤️ Smart Heartbeat:** Система "Пульса" не дает боту считать воркера зависшим, даже если он выполняет долгую задачу (например, ожидание бриджа 30 минут).
* **🔔 Умные уведомления:**
    * **Direct Fallback:** Если бот (Dashboard) выключен или упал, воркеры автоматически отправят уведомление *напрямую* через Telegram API (с пометкой `Direct`). Вы никогда не пропустите важный алерт.
    * **Granular Control:** Настройка типов уведомлений (✅ Success, ❌ Error, 📄 Log) глобально или отдельно для каждого проекта.
* **🗂 Сортировка и Приоритеты:**
    * **Проекты:** Сортировка по Масштабу (общее кол-во аккаунтов), Свежести (Last Active) или Имени.
    * **Воркеры:** "Умный приоритет" (Ошибки всегда сверху -> Активные -> Спящие).
* **🗑 Управление данными:**
    * Создание **JSON-бэкапов** всей базы.
    * Ручное удаление "призраков" (зависших воркеров).
    * Очистка логов ошибок и сброс счетчиков.
* **📄 Smart Logger:** Автоматическая отправка логов (`.log`) и списков неудачных кошельков (`failed wallets`) прямо в чат.

## 🏗 Архитектура

1.  **StatusBot (Dashboard)** — "Экран". Запускается один раз (на вашем ПК или VDS). Читает Redis, рисует кнопки, управляет настройками.
2.  **Workers (Ваши софты)** — "Рабочие". Скрипты на серверах, которые отправляют статистику в Redis. Могут работать в несколько окон под разными именами.
3.  **Redis (Upstash)** — Облачная "нервная система", связывающая всё воедино.

## 🚀 Как запускать (Новые режимы v3.0)

В версии 3.0 вам **не нужно** делать копии папок для разных режимов работы.

### Способ 1. Интерактивный (Вручную)
Просто запустите файл как обычно:
```bash
python main.py
```
Софт остановится и предложит выбрать имя:
> 👉 Введите суффикс (или просто Enter для запуска):

* Нажмете **Enter** — запустится как **Server** (Основной режим).
* Введете **Daily** — запустится как **Server_Daily** (Режим дейликов).
* Введете **Test** — запустится как **Server_Test**.

### Способ 2. Через аргументы (Для профи и .bat файлов)
Чтобы не вводить имя каждый раз, создайте `.bat` файлы (Windows) или `.sh` (Linux) в папке с проектом:

**Файл `Run_Main.bat` (Основа):**
```bat
@echo off
call venv\Scripts\activate
python main.py
pause
```

**Файл `Run_Daily.bat` (Дейлики):**
```bat
@echo off
call venv\Scripts\activate
python main.py --worker Daily
pause
```

Теперь у вас будут работать два независимых окна с разной статистикой, а в боте они объединятся в одну удобную папку!

### Шаг 3. Интеграция в ваш софт

1.  **Копирование модулей:** Скопируйте папку `tgbotintegration/` из этого репозитория в корень вашего проекта.

* `notifications.py` (Связь с Redis, логика прямой отправки, Heartbeat)
* `status_manager.py` (Отправка статусов)
* `monitor.py` (Декоратор, подсчет прогресса, "Тихий режим")
* `stats_map.py` (Карта инвентаря)
* `file_logger.py` (Красивое логирование в файл)

2.  **Библиотеки:** Установите `pip install redis requests`.

3.  **Конфиг:** Добавьте в `config.py` вашего софта настройки:

```python
# --- STATUS MONITORING ---
USE_TG_BOT = True           # True = Включить мониторинг, False = Выключить (Софт будет работать как обычно)
TG_BOT_TOKEN = "..."        # Тот же токен, что у бота
TG_USER_ID = 123456789      # Ваш ID

# --- ГЛАВНОЕ ДЛЯ МЕНЮ:
REDIS_URL = "rediss://..."  # Та же ссылка, что и у бота!
# Имя проекта для декоратора
PROJECT_NAME_FOR_BOT = "HackQuest"  # Или "TruthTensor", "Blum" и т.д.
# Имя для БД Redis
DEVICE_NAME = "Server-1"
# Имя для логов и уведомлений
WORKER_NAME = "Server-1"
# --- LOGGING SETTINGS ---
# Отправлять файл лога (.log) при УСПЕШНОМ завершении?
SEND_LOG_ON_SUCCESS = False  # False = Не спамить файлами, если все ок
# Отправлять файл лога при КРИТИЧЕСКОЙ ОШИБКЕ?
SEND_LOG_ON_ERROR = True     # True = Отправлять для отладки
```

4.  **Main файл:** Вставьте этот код в самое начало `main.py` (до других импортов):

```python
import sys
# [ВАЖНО] Хак для защиты от вылетов (Segmentation fault) на Windows/Linux
sys.modules['hiredis'] = None 

# Импорт логгера из новой папки tgbotintegration
from tgbotintegration.file_logger import install_file_logger
install_file_logger() 

import config
# ... ваши остальные импорты ...
```

5. **Client файл:** Подключение к логике (`client.py`)

Это самый важный этап. Вам нужно научить бота видеть данные вашего софта.

**А. Настройте `tgbotintegration/stats_map.py` (ОБЯЗАТЕЛЬНО):**
Файл `stats_map.py`, который вы скопировали — это **шаблон**. Откройте его и замените примеры на реальные переменные вашего класса.

*Пример:* Если в вашем коде баланс хранится в `self.points`, а не в `self.token_balance`, измените файл так:

```python
def get_display_stats(client) -> dict:
    return {
        # Слева - красивое название для Телеграм
        # Справа - имя переменной в вашем классе (self.points)
        "💰 Coins": getattr(client, 'points', 0),
        "🎫 Tickets": getattr(client, 'tickets', 0),
        "🕊 Twitter": getattr(client, 'twitter_username', "—"),
    }
```

**Б. Добавьте декоратор в код воркера:**
В файле, где находится класс с логикой работы (например, `worker.py` или `client.py`):

1. Импортируйте декоратор.
2. Оберните им метод, который запускает работу.
3. Убедитесь, что класс сохраняет статистику в `self` (например, `self.points = 100`), чтобы `stats_map.py` мог её прочитать.

```python
from tgbotintegration.monitor import monitor_account
import config


class MyClient:
    def __init__(self):
        # Инициализируйте переменные для статистики
        self.points = 0
        self.address = "0x..."

    # Оберните основную функцию работы декоратором
    @monitor_account(config.PROJECT_NAME_FOR_BOT)
    def start_work(self):  # Функция логики в вашем софте может называться как угодно
        # ... ваша логика ...

        # Важно: обновляйте self переменные по ходу работы!
        self.points = get_balance()

        return True
```

**В. ⚠️ Важно для многопоточности:**
Если ваш софт работает в несколько потоков, убедитесь, что вы создаете **новый экземпляр класса** для каждого потока (аккаунта).

## ⚙️ Тонкая настройка (Heartbeat)

В файле `tgbotintegration/notifications.py` можно настроить частоту пульса для долгих задач. Это нужно, чтобы бот не помечал воркера как `OFFLINE`, пока тот ждет транзакцию или спит.

```python
# Включаем "Умный пульс"
ENABLE_HEARTBEAT = True

# Если задача длится дольше этого времени (сек), бот не будет считать воркера упавшим
HEARTBEAT_THRESHOLD = 3600 # 1 час
```

## ❓ FAQ / Решение проблем

* **Как работает группировка папок?**
    Бот смотрит на имена воркеров. Если у вас есть `Server`, `Server_Daily` и `Server_Test`, он видит общий префикс `Server` и автоматически создает для них папку `📂 Server`. Если воркер один (например `Laptop`), он показывается без папки.

* **Софт работает в бесконечном цикле (while True). Статистика сломается?**
    Нет. В v3.0 добавлена функция `reset_global_stats`. Когда софт начинает новый круг (переходит к 1-му аккаунту) или статистика переполнена, счетчики автоматически сбрасываются в ноль. Перезапускать терминал не нужно.

* **Как настроить уведомления отдельно для Daily режима?**
    Настройки уведомлений (Mute/Logs) работают на уровне **Проекта** (`TruthTensor`). Это сделано специально, чтобы не настраивать 50 галочек для каждого под-процесса. Если вы глушите проект — глушатся все его режимы.

* **Я хочу передать софт другу, но не хочу давать доступ к Redis.**
    Просто установите в конфиге `USE_TG_BOT = False`. Скрипт проигнорирует отсутствие настроек Redis, пропустит инициализацию бота и будет работать как обычный скрипт, выводя логи только в консоль.

* **Ошибка `Segmentation fault` / `free(): corrupted`**:
    Вы забыли добавить `sys.modules['hiredis'] = None` в самое начало `main.py` до любых других импортов.

* **Бот выключен, приходят ли уведомления?**
    **Да!** Воркеры автоматически определят, что бот недоступен, и отправят уведомление напрямую через Telegram API (сообщение будет иметь пометку `(Direct)`).

* **Кнопка "Failed Wallets" не появляется:**
    Она появляется только если скрипт упал с критической ошибкой (`Exception`), которую поймал декоратор `@monitor_account`.

* **Как удалить старый проект?**
    Зайдите в `⚙️ Настройки -> 🗑 Управление данными -> Удалить воркеров` и удалите все воркеры этого проекта. Когда воркеров не останется, проект исчезнет из списка.
